FitSync Roadmap / WeChat Mini Program

防忘组、低打扰、训练中专注记录。

FitSync 的方向不是做大而全健身 App，而是把力量训练里最容易被忽略的一件事做顺： 用户在力竭、出汗、走神时，也能快速记录每一组，并清楚知道下一步该做什么。

产品定位

面向 18-40 岁无氧训练用户的轻量级训练记录工具。第一阶段不做饮食、课程、社区、AI 动作纠错或会员体系； 只聚焦训练中快速记组、清楚知道当前进度、减少误触和漏记。

防忘组 防误触 低打扰 黑绿极简 原生微信小程序

核心训练链路

这一条链路是 FitSync 的产品生命线。后续功能都必须服务它，不能打断它。

首页看到今日状态，开始或继续训练。
选动作按胸肩腿背腹快速选择预置动作。
开始设置确认目标组数、休息时间和默认数据。
专注训练大号 + 进入 Sheet，避免复杂入口。
记录本组按住 1.5 秒确认，避免误触。
休息/总结自动倒计时，完成后生成本次记录。

开发路线

Phase 1 / Completed

小程序 MVP 骨架

搭建原生微信小程序目录，完成首页、训练、记录三 Tab；使用本地 storage 保存当前训练和历史记录。

  • 预置动作库：胸、肩、腿、背、腹。
  • 训练主链路：选择动作、记录组数、休息、总结。
  • 训练记录页：展示历史训练和每组明细。
Phase 2 / Completed + Polish

训练中交互增强

围绕防误触和训练节奏做增强，但仍保持轻量。

  • 1.5 秒延迟确认，按钮文案为“记录本组”，保留进度反馈。
  • 记录后 3 秒撤销，撤销可恢复组数、停止休息。
  • 休息结束轻震动 + 视觉提示，不做音效。
  • 漏记提醒：训练页可记录状态停留 120 秒后提示补记。
  • 开始设置层：训练前确认目标组数和休息时间。
  • 上一组信息面板：点击展开查看完成时间和正式组进度。
Phase 3 / Completed

动作内容与自定义能力

让小程序从“可展示 demo”走向“可长期使用工具”。

  • 补全动作库：胸、背、肩、腿、手臂、核心 6 分类，每类 6-8 个常见动作。
  • 自定义动作：名称、分类、角色、默认组数、默认重量、默认次数。
  • 常用动作：按当前分类展示最近练过的动作。
Phase 4 / Next

总结卡与展示包装

训练完成后给用户一点情绪反馈，但不强制社交分享。

  • 截图风格总结卡：组数、训练量、时长、完成时间。
  • 克制文案：Quiet work counts too / Built in silence 等方向。
  • 主题切换：黑绿主视觉为主，黑红/黑琥珀方向后续再评估。
  • Tab 图标：81x81 PNG，保持黑绿极简风格。
Phase 5 / Later

云端与长期记录

只有在核心训练流程稳定后，再考虑账号和云同步，避免过早复杂化。

  • 微信登录与云开发同步。
  • 跨设备恢复训练记录。
  • 周/月训练量趋势和动作进步趋势。

架构尺度

Keep

坚持做小而完整

  • 原生 JS + WXML + WXSS。
  • 页面只保留首页、训练、记录。
  • storage 封装在 utils，不散落在页面。
  • 训练计算逻辑放在 trainingSession.js。
  • 新功能优先围绕训练主链路。
Avoid

暂时不要做重

  • 不引入 Taro、TypeScript、状态库或 UI 库。
  • 不做饮食、课程、社区和排行榜。
  • 不做复杂训练计划生成。
  • 不在训练中堆太多统计图。
  • 不让用户每组都填复杂表单。
