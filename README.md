## 一、产品定位

力量训练者最大的痛点不是"记不下来"，而是"练到第三、四组手酸手抖时，记不下来"。

| 维度 | KEEP / 训记 / Strong | **组间歇PRO** |
|---|---|---|
| 记录一组所需点击 | 3-5 次 | **1 次**（长按 1.5 秒） |
| 组间计时 | 手动 | **自动**（时间戳制、切后台零误差续走） |
| 漏记提醒 | 无 | **2 分钟无记录自动浮层提醒** |
| 防误触 | 常规 44px 按钮 | **80px 大按钮 + 长按确认 + 3 秒撤销** |
| 网络环境 | 弱网卡顿 | **本地优先 + 静默同步** |

**核心 Insight**：训练中的手机交互应该像秒表，而不是电子表格。

## 二、用户调研（20+ 力量训练用户深度访谈）

| 痛点类型 | 用户原话 | 设计对策 |
|---|---|---|
| **防忘组**（认知成本） | "练到第三、四组就忘了上组多重 / 该第几组" | 进度条 + 圆点指示 + 漏记提醒 + 上一组数据自动复用 |
| **防误触**（操作成本） | "手汗手抖容易点错" | 大号 `+` 按钮 + 底部 Sheet + 长按 1.5 秒 + 3 秒撤销 |
| **低打扰**（防打断） | "休息间隙不想点 3-5 下屏幕" | 自动复制上一组 + 快捷步长 ±2.5kg + 自动休息倒计时 + 静默云同步 |

## 三、设计哲学

1. **80px `+` 按钮**：健身时手指出汗、颤抖，小按钮误触率高。
2. **默认复制上一组数据**：80% 的情况下用户不改重量。
3. **快捷微调代替输入框**：±2.5kg / ±1 次的按钮比键盘输入快一个数量级。
4. **3 秒撤销**：误操作后的后悔期。不做二次确认弹窗——会打断节奏。
5. **自动组间计时**：确认一组后自动开始倒计时，时间戳制而非数值制，切后台再回来零误差。
6. **漏记提醒**：训练中 2 分钟无新记录自动浮层兜底，专治"第三、四组忘了"。

## 四、技术栈

| 类别 | 选型 | 理由 |
|---|---|---|
| **小程序框架** | 微信小程序原生（WXML + WXSS + JS） | 体积小、审核友好、不引入 Taro/uni-app 跨端复杂度 |
| **后端** | 微信云开发（CloudBase） | 个人主体可开、免运维、原生鉴权 |
| **数据层** | 本地优先 + 静默云同步 | 健身房弱网是常态，记录动作不能被网络等待阻塞 |
| **测试** | Node.js + 自研 in-memory mock | 0 外部依赖，177 项断言 4 套测试全绿 |
| **设计令牌** | `app.wxss` 深色 `#0a0a0a` + 琥珀绿 `#22c55e` | 健身房光线偏暗，深色不抢注意力 |

## 五、核心架构约定

1. **本地优先** — 训练数据先写 `wx.storage` 再异步上云。任何网络等待都不允许阻塞记录动作。
2. **优雅降级** — `utils/config.js` 未填 `cloudEnv` 时必须能完整跑通主流程。
3. **登录永不失败** — `ensureLogin()` 永不 reject，失败降级为本地 guest id。
4. **幂等写入** — `recordId = session-${startedAt}` 客户端生成；云端比较 `completedAt` 防止旧数据覆盖。
5. **分层职责** — Pages 只做 UI 编排 / Services 做业务编排 / Utils 做纯函数。
6. **同步失败必须静默** — 失败一律进重试队列，绝不弹 toast 打断训练节奏。
