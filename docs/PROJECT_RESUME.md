## 版本 C · 完整版（用于面试深聊时口头展开,约 500 字）

**组间歇PRO — 微信小程序「组间休息一次点击完成记录」的力量训练记录工具**　·　2026.03 — 2026.09　·　独立项目　·　[GitHub](https://github.com/TWTYS1/-FITsync)

### 需求

线下健身房对 20+ 名力量训练用户的深度访谈中,梳理出组间休息场景的两类核心障碍:**忘记当前组数**(认知成本)与**记录链路过重**(操作成本)。结合对 KEEP、训记两款主流产品的拆解,发现它们在"训练中专注模式"普遍存在按钮易误触、记录路径过长等问题。以此确定 FitSync 小程序的差异化切入点:**组间休息这一场景被所有人做重了**。

### 方案

围绕「防忘组、防误触、低打扰」三大原则设计训练中专注模式:

- **防误触**:80px 大号 `+` 按钮 + 底部 Sheet 数据确认 + 长按 1.5 秒确认 + 3 秒可撤销浮层
- **防忘组**:上一组重量 / 次数自动复用 + 进度条 + 圆点指示器 + 训练中 2 分钟无记录自动漏记提醒
- **低打扰**:快捷步长按钮(±2.5kg / ±1 次)代替键盘输入 + 自动休息倒计时(时间戳制,切后台零误差)+ 本地优先架构,云同步全程静默,永不为网络等待让路

### 推进

- **调研**:线下 20+ 用户访谈,形成「训练频率 / 记录习惯 / 痛点优先级」三类标签;KEEP / 训记 拆解对照表
- **选型**:微信小程序原生 + 微信云开发,刻意不引入 Taro / TypeScript / UI 组件库,以降低 MVP 复杂度与审核风险
- **架构**:Pages / Services / Utils 三层职责清晰,确保将来换自建后端只改 `services/sync.js` 一个文件
- **测试**:自研 in-memory mock 框架,4 套测试 / 177 项断言全绿(训练会话纯逻辑 36 / 同步合并 24 / 服务编排 34 / 模块依赖链 103)
- **合规**:完成服务类目(工具>健康管理)、隐私协议、订阅消息授权节流、备案备注文案等上线前合规项
- **品牌**:经历 FitSync → 组间记 → 组间歇PRO 三次命名迭代,完成注册、Logo、官网介绍稿

### 结果

- 交付**完整可上线**的微信小程序 MVP(代码 + 测试 + 文档 + 素材 + 上线指南)
- 在主产品赛道"工具>健康管理"个人主体免资质前提下,完成商业化路径的四阶段规划(纯免费做留存 → 流量主 → Pro 订阅 → 健身周边带货)
- 通过文档化交付(Word 作品说明书 / 交互指南 / Markdown 技术路线 / 测试用例)沉淀项目全链路资产,可直接用于公众号介绍、面试讲解、团队交接
